# LumaTrace Documentation

English is the primary documentation language. Chinese readers can start with [../README.zh-CN.md](../README.zh-CN.md), while the detailed docs in this directory remain English-first unless a document explicitly says otherwise.

LumaTrace is a clean-room, local-first device metrics testing toolkit. MVP-A focuses on a reliable backend loop, MVP-B adds the first desktop web UI, Android Beta adds non-root Android metrics and diagnostics, PC Beta adds Windows process metrics plus explicit PresentMon CSV capture, Tauri packaging hardening adds sidecar/security checks, and iOS Beta adds Xcode/xcrun discovery plus explicit manual xctrace CSV import.

## Project Goals

- Provide a unified model for devices, targets, metric events, availability, sessions, markers, reports, tool status, and diagnostics.
- Keep all metrics honest by attaching source, precision, confidence, and availability.
- Run without real devices through a MockCollector, so UI, API, storage, streams, and reports can be developed and tested end to end.
- Discover Android devices and package targets through non-root adb when Android SDK Platform Tools are available.
- Stay local by default. MVP-A does not upload data and does not collect real logs.

## Architecture Overview

The monorepo currently contains:

- `packages/core`: models, metrics, stats, command runner, collector interface, errors.
- `packages/collectors/mock`: deterministic mock collector and mock profiles.
- `packages/collectors/android`: adb detection, Android discovery, package/PID/UID parsers, Android CPU/memory/battery/network sampling, Android FPS pre-research parsers/probe, and Android availability.
- `packages/collectors/pc`: Windows process discovery, PID-bound CPU/memory sampling, PresentMon detection/capture adapter, and PC diagnostics.
- `packages/collectors/ios`: Xcode/xcrun discovery, simulator app target parsing, manual xctrace CSV import parsing/mapping, and iOS availability.
- `packages/storage`: SQLite schema, migrations, repositories, JSON serialization.
- `packages/report`: summary generation and JSON, CSV, HTML exporters.
- `apps/local-server`: Fastify REST API, WebSocket stream, runtime manager, services, MVP-A backend loop.
- `apps/desktop`: React/Vite MVP-B shell, API client, WebSocket client, and first pages.

## MVP-A Backend Loop

1. Discover mock devices.
2. List mock targets.
3. Create a session.
4. Start the session runtime.
5. Read `MetricEvent` values from MockCollector.
6. Write recent metrics to memory ring buffer.
7. Broadcast realtime metrics over WebSocket.
8. Batch persist raw metrics to SQLite.
9. Stop the session and flush pending metrics.
10. Generate a report summary and export JSON, CSV, or static HTML.

## Mock Data

Mock metrics are generated for development and tests only. They use `source: "mock"` and are not real device data. They are useful for validating charts, reports, storage, APIs, and WebSocket behavior before platform collectors exist.

## Local First

MVP-A stores data locally in SQLite. It does not upload metrics or reports. Reports are local strings or local files generated by tests/scripts.

## MVP-B UI Shell

The UI is a Vite app that connects to local-server. MockCollector remains available for demos. Android devices can now stream CPU, memory, battery, and network metrics when the target app process is already running.

## Platform Betas

Android setup is documented in [android-setup.md](android-setup.md). Android Beta does not require root, does not use private APIs, does not collect logcat by default, and only starts/stops apps through explicit user/config actions. FPS/frame-time remains `experimental`.

PC Beta supports Windows process CPU/memory and explicit PresentMon CSV capture. PresentMon is default off, missing/unmatched/ambiguous data does not produce FPS, and GPU/ETW SDK capture remains future work.

iOS Beta is documented in [ios-beta.md](ios-beta.md). It uses public Xcode command line tools for discovery on macOS and supports explicit manual xctrace CSV import. It does not start xctrace recording, run live iOS sessions, collect syslog/logs, use private APIs, or fabricate missing metrics.

## Run

```bash
pnpm install
pnpm dev:server
pnpm dev:desktop
```

Then call:

```bash
curl http://127.0.0.1:3100/api/health
```

## Test

pnpm verify:mvp-a
pnpm verify:android-beta
pnpm verify:pc-beta
pnpm verify:ios-beta
pnpm verify:packaging-hardening
