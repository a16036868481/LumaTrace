# LumaTrace 使用说明

[下载](https://github.com/a16036868481/LumaTrace/releases/tag/v1.0.3-preview.1) · [微软商店](https://apps.microsoft.com/detail/9P3KNQZMFBM8) · [English guide](user-guide.md) · [项目首页](../README.zh-CN.md)

## 安装与准备

准备一台 Windows 11 x64 电脑。在 [1.0.3 预览版发布页](https://github.com/a16036868481/LumaTrace/releases/tag/v1.0.3-preview.1)选择需要的文件：

- `LumaTrace-1.0.3-windows-x64-setup.exe`：运行安装程序，完成后打开 LumaTrace。
- `LumaTrace-1.0.3-windows-x64-portable.zip`：完整解压到可写的文件夹，运行 `lumatrace-desktop.exe`；让 `binaries` 文件夹与可执行文件保持在同一目录。
- `SHA256SUMS.txt`：用于校验下载的文件。

GitHub 预览版未签名，Windows 可能提示未知发布者或 SmartScreen 警告；请核对来源，不要关闭系统防护。[微软商店](https://apps.microsoft.com/detail/9P3KNQZMFBM8)提供当前地区已批准的版本，可能与本次预览版不同。GitHub 的源代码压缩包不是可直接运行的软件。

软件需要 Microsoft WebView2 Runtime。安装版发现缺少时会联网下载，因此首次安装可能需要网络；便携版用户应先从[微软官方页面](https://developer.microsoft.com/microsoft-edge/webview2/)安装 WebView2 Runtime，再启动 LumaTrace。

普通用户无需安装 Node.js 或 pnpm。Android 测试需要 **ADB**，Windows FPS 需要 **PresentMon**，这两个工具未随软件打包。

在左侧底部的 **Language** 选择 **简体中文** 或其他语言。首次启动默认为英文，内置 101 种语言/地区选项。请在开始测试前选择好语言，本次生成的报告会使用该语言。

点击 **设置报告目录**，选择有写入权限且空间充足的文件夹。建议在测试开始前设置；以后点击 **打开报告目录** 即可找到文件。

## 测试 Windows 应用或游戏

1. 先打开需要测试的应用或游戏。
2. 在 LumaTrace 首页选择 **Windows 本机**。
3. 搜索名称并选中真正运行应用的进程。如果是在列表出现后才打开的游戏，点击 **开始测试** 旁的刷新按钮。
4. 不需要日志时，保持 **输出日志到报告目录** 不勾选。
5. 点击 **开始测试**，返回应用或游戏，进行需要测量的操作。
6. 完成后点击 **结束测试**，打开 **测试结果** 查看总结和曲线。

FPS、CPU、GPU、内存、GPU 功耗、GPU 温度的曲线默认全部勾选。勾选框用于控制要显示的曲线；能否获取数据取决于应用、硬件、驱动和权限，不是勾选后就一定有数据。

请选游戏本体进程，而不是启动器。对于包含多个进程的应用，内存测量的是选中的进程，不会自动加上所有辅助进程。

### FPS 与 Windows 权限

软件会自动尝试通过 PresentMon 采集实时 FPS。如果缺少工具，可从官方 [PresentMon 发布页](https://github.com/GameTechDev/PresentMon/releases)安装兼容版本。高级用户可用 `LUMATRACE_PRESENTMON_PATH` 指定其可执行文件，再重新打开 LumaTrace。

首次配置 Windows 采集权限时可能出现系统提示，需要管理员批准，并可能需要注销、重新登录 Windows 后生效；普通 CPU、内存测试仍可继续。软件不会静默获得管理员权限。

如果 FPS 没有数据，请让游戏保持实际渲染，并确认选中的进程仍在运行。受保护的进程、不支持的渲染方式、权限或帧事件匹配失败都可能导致采集不到。加载效果表示正在等待数据，不保证最终一定能提供数据。

## 测试 Android App

LumaTrace 在 Windows 电脑上运行，手机无需安装配套 App。

1. 在手机中开启 **开发者选项** 和 **USB 调试**。不同品牌的菜单位置可能不同。
2. 使用支持数据传输的 USB 线连接电脑，解锁手机，并同意 **允许 USB 调试**。
3. 在手机上打开待测应用或游戏，让它处于前台。
4. 在 LumaTrace 中选择 **Android 手机**，再选择已连接的设备。
5. 等待 **手机当前打开的 App** 显示应用或包名，然后点击 **开始测试**。
6. 正常使用手机，完成测试场景后，回到 LumaTrace 点击 **结束测试**。

如果提示缺少 ADB，请安装官方 [Android SDK Platform Tools](https://developer.android.com/tools/releases/platform-tools)，将 `adb` 加入 PATH 后重新打开 LumaTrace。高级用户也可以用 `LUMATRACE_ADB_PATH` 指定 ADB 可执行文件的位置。

Android 曲线包含 FPS、帧时间、CPU、内存、电量和电池温度；电池温度不是 CPU 或 GPU 温度。报告还可能包含电量消耗及网络数据。FPS 受设备和应用开放的数据限制，并非每款手机、每个游戏都支持。无需 ROOT；当前不支持 iOS。

## 加载效果与没有数据的情况

识别设备、识别前台 App 和启动采集时会显示加载效果。CPU、网络等指标需要先建立采样基线，再计算变化；部分采集器的第一条结果会来得更慢。

某个指标收到真实数据后，就会显示数值和曲线。缺失样本不会按 0 绘制。如果一直没有数据，请按下面的情况检查，不要把空白理解为没有资源占用。

| 现象 | 检查方法 |
| --- | --- |
| 找不到游戏或进程 | 确认已经打开游戏，清除搜索条件，点击刷新。 |
| 找不到 Android 手机 | 使用数据线、解锁手机、开启 USB 调试并同意电脑授权，确认 ADB 已安装。 |
| 手机应用识别不对 | 在所选手机上把目标 App 切到前台，然后再开始测试。 |
| FPS 一直加载或未采集 | 确认进程/应用正在渲染；Windows 检查 PresentMon 和权限，Android 检查设备及渲染方式兼容性。 |
| GPU、功耗、温度未采集 | 驱动或传感器可能没有提供对应数据，仅勾选曲线无法补出读数。 |
| 曲线停止更新 | 检查 USB 是否断开、目标进程是否退出。进程重新启动后，请重新测试。 |
| 无法连接本地服务 | 尽可能先结束当前测试，再进入 **修复/提交BUG → 一键修复**。 |
| 报告目录没有文件 | 检查写入权限和剩余空间，先查看软件里的 **测试结果**，换一个目录后再测试。 |

## 查看结果与报告

点击 **测试结果**，在左侧列表选择一次测试。右侧按流畅度、应用资源占用和设备指标展示结果。

| 指标 | 含义 |
| --- | --- |
| 平均 FPS | 测试时段的平均帧率。对比时应保持场景、画质及帧率上限一致。 |
| 1% Low FPS | 反映帧率较低的一端，与平均 FPS 差距较大时，可能存在明显波动。 |
| P95 帧时间 | 单帧耗时的较高分位数，单位毫秒；一般越低，长帧越少。 |
| CPU | 按采集器测量口径统计的目标应用或进程 CPU 使用率。 |
| 内存 | Windows 显示所选进程的工作集内存。Android 使用设备提供的应用内存数据，统计口径可能不同。 |
| GPU | 数据源支持时，显示进程 GPU 使用率。 |
| GPU 功耗、温度 | 显卡设备的传感器读数，不是某个应用的独占功耗，也不是整机功耗。 |
| Android 网络 | 优先统计 App/UID 的流量；退回设备级统计时可能包含其他应用，具体看指标详情。 |

FPS 性能总结是通用参考。例如锁定 30 FPS 的游戏，不宜与不锁帧游戏直接比较。没有采集到的指标保持 **N/A / 未采集**，详情保留来源、精度、可信度和可用情况。

结束测试后，报告目录中会出现本次测试的独立文件夹：

```text
你选择的报告目录/
  测试名称_年-月-日_时-分-秒-毫秒_唯一标识/
    report.html
    report.csv
    report.json
    android-logcat.log 或 windows-session.log  （勾选后才输出）
```

用浏览器打开 HTML 查看图文报告，用表格软件打开 CSV 查看逐条指标，JSON 可用于进一步处理数据。名称、时间和后缀可让重复测试分别保存。

垃圾桶按钮可删除单条结果。**清空全部** 经确认后删除已完成测试的本地记录和采集数据，运行中的测试会保留。报告目录中已经导出的文件也会保留，如需删除这些文件，请在资源管理器中单独管理。

## 可选日志与隐私

需要日志时，在开始前勾选 **输出日志到报告目录**。该选项默认关闭，新测试会恢复为未勾选。

- **Android：** 导出测试期间带时间的 ADB logcat 文本并脱敏敏感内容。设备日志缓冲区和输出大小限制可能导致截断。采集失败时会记录失败，不会拿伪造日志替代。
- **Windows：** 导出带时间的 LumaTrace 会话和采集记录，不是被测程序自身的私有日志，也不是完整 Windows 事件日志。

报告和日志保存在本机，并对敏感值进行脱敏。公开分享前仍请检查文件和截图。

需要帮助时，可以[提交 GitHub Bug](https://github.com/a16036868481/LumaTrace/issues/new?template=bug_report.yml)，附上版本、设备和系统信息、复现步骤及相关脱敏材料。
